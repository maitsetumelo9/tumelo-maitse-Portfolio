Web Security Practice Lab

Explore three common vulnerability classes using safe, fictional simulations. The lab displays unsafe patterns for learning but does not execute payloads, connect to a database, or contact a target.

Safe sandbox: all demonstrations run locally. Only test systems you own or are explicitly authorised to assess.

Cross-site scripting (XSS)

See why untrusted input must be treated as text. Try a harmless markup string; it will be displayed as text, not executed.

SQL injection

Inspect how string concatenation can alter a query. This is a text-only illustration; the query is never sent to a database.

Broken access control / IDOR

Choose a fictional signed-in user and a report ID. Compare a deliberately weak illustrative decision with an ownership check.

Analyst / developer notes

  • XSS: use safe DOM APIs such as textContent for plain text and context-aware encoding where required.
  • SQL injection: use parameterized queries; never build SQL by concatenating untrusted values.
  • Access control: enforce server-side authorization for each resource and request, not just in the interface.

For every finding, record the affected component, reproducible evidence, potential impact, remediation, and retest result.
